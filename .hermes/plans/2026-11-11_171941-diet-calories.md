# Plan: calories without the counting

## Goal

Diet records a calorie number for each entry with as little effort as possible. You get it in one of four ways:
- type it;
- type the kcal per 100 g and how much you ate, and Klean does the arithmetic;
- leave it blank, and Klean fills it from what you logged before;
- or, if you've set up an AI, the AI estimates it.

On top of that: a daily goal bar, and a one-tap "Copy today" for pasting into any LLM.

## What the user asked (verbatim, condensed)

1. "have the slot to record calories, sometimes I do know the calorie count."
2. "record calories per weight and automatically calculate … 150 kcal for 100g serving and I had 200g would be 300kcal … have the tooltip say this syntax."
3. "copy what I've eaten for the day along with the calorie count if present, so I can paste it into any LLM."
4. "when I leave the calorie slot empty try to infer the calorie count for that item from previous entries (I don't think that needs an LLM), otherwise immediately when I add the item ask the LLM to fill in the calorie estimate."
5. "If I specify g in the calorie slot that means I know the quantity but I don't know the calorie count, get the estimate from the LLM or from historical figures and adjust it to the quantity."
6. "a progress bar … calories eaten out of my calorie goal, configured from the module's settings."
7. "all LLM features optional and model-provider agnostic."
8. "I really really hate calorie counting, so make it as easy and seamless as possible."

**The syntax, decided:** `KCAL x PER x ATE`. The user's example "150x100x150" doesn't match their own numbers: 150 kcal per 100 g, eating 200 g, gives 300 kcal. So `150x100x200` = 150 × 200 / 100 = **300 kcal**. The tooltip and live preview show the result before saving, so a slip is visible at once. This is open question 1.

## Design (the easy path first)

**One place to type: the food text itself.** Calories can ride along at the end of what you type or say:

| You type or say | Saved as |
|---|---|
| `banana` | text "banana"; calories filled for you (history, then AI) |
| `oatmeal 150 kcal` / `oatmeal 150kcal` / `oatmeal 150 cal` | "oatmeal", **150 kcal** (yours) |
| `rice 200g` / `rice 200 g` / `rice 0.2 kg` | "rice", 200 g, calories filled for you and scaled to 200 g |
| `chips 150x100x200` (also `×`, `*`, `150kcal x 100g x 200g`) | "chips", **300 kcal** (yours), 200 g |

This works everywhere at once, voice included ("rice two hundred grams" becomes "rice 200 grams" through the recogniser), with no extra field.

**The visible slot.** When the capture sheet is aimed at Food and **Show calories** is on, a small second field labelled `kcal` sits on the same row as the text field, to its right and about 96 dp wide. It accepts the same syntax: `300`, `200g`, `150x100x200`.
- **Live preview.** Its supporting text shows the result as you type: `= 300 kcal`, `200 g · Klean will fill in the calories`, or `Not sure what that means` for anything unparseable. Saving then ignores the field.
- **Tooltip.** An ⓘ next to it opens a `RichTooltip`:

  > Type the calories (300), or how much you ate (200g), or kcal per amount × what you ate (150x100x200 = 150 kcal per 100 g, ate 200 g → 300 kcal). Leave it empty and Klean fills it in.

- **Precedence.** A value in the slot wins over a token typed in the text.

**Filling in**, when you didn't give calories:
1. **History (on-device, no AI).** Find an earlier entry with the same food, by name after normalising.
   - It had grams and you gave grams: scale per gram.
   - You gave no grams: use its calories as they were.
   - You gave grams but it had none: use its calories only if its text is identical; otherwise go on to step 2.

   Use the most recent match. Search the last 365 days, only live entries with calories, and never entries whose own calories came from history (only USER or AI), so estimates don't compound. The result is marked "from earlier".
2. **AI** (only if a provider is assigned to *Calorie estimates* in Settings › AI). Run a new `CalorieFillWorker` right after saving: expedited, needs the network only if the provider does. It sends the food text and the grams, if known. The result is marked "estimate".
3. Otherwise the entry has no calories. That's fine and never nagged about.

**Display.**
- Calories show only when **Show calories** is on.
- Your own number shows plainly (`300 kcal`). Filled-in numbers show with `≈` (`≈ 105 kcal`).
- Totals show `≈` if any part is estimated.

**Goal bar.** In Diet settings, set a *Daily calorie goal* (blank = no bar). The Diet hero then shows a progress bar and `1,240 of 2,000 kcal`.
- **Over the goal:** the bar stays full in the same colour and the text reads `2,240 of 2,000 kcal`. No red, no "over".
- **Partial days:** entries without calories count as zero. When some of today's entries have no calories, a quiet line says `3 foods without calories`, with a "Fill in" action when an AI is assigned.

**Copy today.**
- Diet ⋮ → **Copy today**, and on a past day ⋮ → **Copy this day**. Both put this on the clipboard:
  ```
  What I ate on Wednesday, 11 November 2026
  09:00  oatmeal: 150 kcal
  11:27  banana: ≈ 105 kcal
  11:45  McDonald's cheeseburger: 300 kcal
  13:10  salad
  Total: ≈ 555 kcal (goal 2,000 kcal) · 1 food without calories
  ```
- Times follow the phone's 12/24 h setting.
- Below Android 13 a snackbar says "Copied". On 13+ the system shows its own confirmation, so Klean adds nothing.
- With **Show calories** off, the calories are left out of the copied text too.

**Fill in missing calories.** Diet ⋮ → **Fill in calories** (shown only when some of today's entries lack calories) re-runs history, then AI, for each of them.

**Where an entry's calories come from.**
- An entry's kcal is `food_entry.kcal` if set. Otherwise it falls back to the sum of AI items (`knownCalories(items)`) for old entries.
- When `FoodEnrichmentWorker` writes items with calories and the entry has no `kcal`, it also sets `kcal = sum` with source AI. From then on the entry's number is the single truth.

```kotlin
package app.klean.shared.diet

import kotlin.math.roundToInt

/** What the calorie slot (or the end of a food text) says. See plan 2026-11-11 "calories without the counting". */
sealed interface CalorieInput {
    data object Empty : CalorieInput
    data object Invalid : CalorieInput
    /** The user knows the calories. */
    data class Kcal(val kcal: Int) : CalorieInput
    /** The user knows how much, not the calories: Klean fills them in for this amount. */
    data class Grams(val grams: Int) : CalorieInput
    /** "150x100x200": [kcal] per [perGrams], ate [ateGrams] → [total]. */
    data class PerAmount(val kcal: Int, val perGrams: Int, val ateGrams: Int, val total: Int) : CalorieInput

    companion object {
        const val MAX_KCAL = 20_000
        private const val NUM = """(\d+(?:[.,]\d+)?)"""
        private val KCAL = Regex("""^$NUM\s*(?:k?cal(?:ories)?)?$""", RegexOption.IGNORE_CASE)
        private val GRAMS = Regex("""^$NUM\s*(g|gr|grams?|kg)$""", RegexOption.IGNORE_CASE)
        private val PER = Regex(
            """^$NUM\s*(?:k?cal)?\s*[x×*]\s*$NUM\s*(?:g|gr|grams?)?\s*[x×*]\s*$NUM\s*(?:g|gr|grams?)?$""",
            RegexOption.IGNORE_CASE,
        )
        private val TRAILING = Regex(
            """^(.*\S)\s+((?:\d[\d.,]*\s*(?:k?cal(?:ories)?|g|gr|grams?|kg))|(?:\d[\d.,]*\s*(?:k?cal)?\s*[x×*]\s*\d[\d.,]*\s*(?:g|gr|grams?)?\s*[x×*]\s*\d[\d.,]*\s*(?:g|gr|grams?)?))$""",
            RegexOption.IGNORE_CASE,
        )

        private fun num(s: String): Double? = s.replace(',', '.').toDoubleOrNull()

        fun parse(raw: String): CalorieInput {
            val s = raw.trim()
            if (s.isEmpty()) return Empty
            PER.matchEntire(s)?.let { m ->
                val (k, per, ate) = m.destructured
                val kcal = num(k) ?: return Invalid
                val perG = num(per) ?: return Invalid
                val ateG = num(ate) ?: return Invalid
                if (kcal <= 0 || perG <= 0 || ateG <= 0) return Invalid
                val total = (kcal * ateG / perG).roundToInt()
                return if (total in 1..MAX_KCAL) PerAmount(kcal.roundToInt(), perG.roundToInt(), ateG.roundToInt(), total) else Invalid
            }
            GRAMS.matchEntire(s)?.let { m ->
                val (n, unit) = m.destructured
                val g = (num(n) ?: return Invalid) * (if (unit.equals("kg", true)) 1000 else 1)
                return if (g >= 1 && g <= 10_000) Grams(g.roundToInt()) else Invalid
            }
            KCAL.matchEntire(s)?.let { m ->
                val k = num(m.groupValues[1]) ?: return Invalid
                return if (k >= 1 && k <= MAX_KCAL) Kcal(k.roundToInt()) else Invalid
            }
            return Invalid
        }

        /** "rice 200g" → ("rice", Grams(200)). A bare trailing number stays part of the food. */
        fun splitTrailing(text: String): Pair<String, CalorieInput> {
            val m = TRAILING.matchEntire(text.trim()) ?: return text.trim() to Empty
            val parsed = parse(m.groupValues[2])
            return if (parsed is Kcal || parsed is Grams || parsed is PerAmount) m.groupValues[1].trim() to parsed else text.trim() to Empty
        }
    }
}

fun normaliseFood(s: String): String =
    s.lowercase().replace("'", "").replace("’", "").replace(Regex("[^\\p{L}\\p{N} ]"), " ").replace(Regex("\\s+"), " ").trim()

fun historyKcal(food: String, grams: Int?, past: List<PastEntry>): Int? {
    val key = normaliseFood(food)
    val same = past.filter { it.source != KcalSource.HISTORY && normaliseFood(it.text) == key }.sortedByDescending { it.eatenAt }
    if (grams != null) {
        val withGrams = same.firstOrNull { it.grams != null && it.grams > 0 } ?: return null
        return (withGrams.kcal.toDouble() / withGrams.grams!! * grams).roundToInt()
    }
    return same.firstOrNull()?.kcal
}

/** "1,240 of 2,000 kcal" over a calm bar. Over the goal the bar is simply full — no warning colour. */
@Composable
fun CalorieProgress(eaten: Int, goal: Int, estimated: Boolean, modifier: Modifier = Modifier) {
    val fraction = if (goal <= 0) 0f else (eaten.toFloat() / goal).coerceIn(0f, 1f)
    val nf = java.text.NumberFormat.getIntegerInstance()
    val text = stringResource(R.string.design_kcal_of_goal, (if (estimated) "≈ " else "") + nf.format(eaten), nf.format(goal))
    Column(modifier.semantics(mergeDescendants = true) { progressBarRangeInfo = ProgressBarRangeInfo(fraction, 0f..1f) }) {
        Text(text, style = MaterialTheme.typography.titleMedium)
        Spacer(Modifier.height(Space.xs))
        LinearWavyProgressIndicator(progress = { fraction }, modifier = Modifier.fillMaxWidth())
    }
}
```

## Risks, trade-offs, open questions

1. **The syntax.** The user's example `150x100x150` doesn't give 300. The plan uses `kcal x per-amount x eaten` (`150x100x200` = 300) and shows the result live, so a typo is caught before saving. *Open:* confirm the order. A per-serving shorthand like `150x2` = two servings is left out (YAGNI) until asked for.
2. **Stripping the trailing token from `raw_text`** changes what's stored compared with what was typed: "rice 200g" is saved as "rice" with 200 g. That keeps names clean for history matching and "Log again". The entry screen shows the amount, so nothing is lost. A bare number is never treated as calories, so "2 eggs" and "coffee 2" stay intact.
3. **History matching is by exact normalised name.** "banana" and "a banana" won't match. That's deliberate: fuzzy matching would put wrong numbers in silently. Phase 4 can later add a "the same as…" suggestion. *Open:* is exact-match enough to start with?
4. **Double AI calls.** When ENTRY_PARSE and CALORIE_ESTIMATE are both assigned to different providers, both run. The existing behaviour stays, and the filler skips the AI when the parse will cover it (4.4 de-dup).
5. **Show calories stays off by default** for other users. Calories are opt-in, so nobody is pushed into counting. The user turns it on once.
6. **Goal over-run is neutral by design**: no red, no "over", no streaks. That follows the app's no-guilt copy rule.
7. **Sync conflicts.** `kcal` is last-write-wins with the row, like every other column, so an AI fill racing a user edit on another device could overwrite it. The filler writes only while `kcal` is null and `updatedAt` is unchanged, which keeps the window tiny.
8. **Web.** The web client doesn't show or set calories yet. That's a follow-up for the web lane (add to `TASKS.md` › Follow-ups).
9. **The clutter budget.** The capture sheet gets a second input only for Food with Show calories on, which is allowed under the forms exception. Everywhere else is unchanged.
