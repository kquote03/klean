## How to work here (essentials; details in AGENTS.md and the brief)

- **Builds:** everything runs through Nix. Use `cd <repo> && flock ~/.hermes/cache/scratch/gradle.lock nix develop -c ./gradlew <tasks> --console=plain -Pkotlin.compiler.execution.strategy=in-process`. The machine has 14 GB, so only one Gradle build runs at a time; the lock enforces this.
- **Gate:**
  ```
  assembleDebug :app:assembleDebugAndroidTest :shared:jvmTest testDebugUnitTest :backend:test
  ```
- **Device:** Waydroid only (`192.168.240.112:5555`, Android 13).
  - Hold `~/.hermes/cache/scratch/waydroid.lock` while using it.
  - Install with `adb install -r -d`.
  - Never trigger a camera intent: it crashes the whole container.
  - If the container shows FROZEN after a restart, run `waydroid show-full-ui`.
  - The Pixel is for the user's sessions only.
- **Shared subagent brief:** `~/.hermes/cache/scratch/klean-subagent-brief.md`. It holds all the rules, Waydroid tips and contracts, and has "State update" sections at the end.
- **Commits and merges:**
  - Commit after every task (Conventional Commits) and push.
  - Lanes work in `../klean-<lane>` git worktrees on branches, and the parent merges them one at a time, running the gate after each merge.
  - Expected merge conflicts: TASKS.md (keep both sides), `KleanApp.kt` (union of startup steps), `Channels.kt` and the debug manifests (union).
  - Lanes must not change the Room schema.
- **Holistic contracts every module implements** (`core/ui/src/main/kotlin/app/klean/core/ui/module/`):
  - `KleanModule`, `DashboardSummaryProvider`, `DayActivityProvider`, `StatusLineProvider` (take repositories through `dagger.Lazy`), `TodayItemsProvider`, `OnboardingStepProvider`
  - call `StatusRefresh` after writes
  - `CaptureHandler` using the `RuleCaptureClassifier` action constants
  - `Reschedulable` for alarms
- **Usage limit:** the 5-hour limit is the main constraint. Run at most 2–3 lanes at once, and tell agents to commit early, because only commits survive an interruption.
